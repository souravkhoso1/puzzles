# Puzzle Hub

A static, GitHub Pages–only collection of free daily puzzles. No backend, no
build step, no frameworks — same approach as the original `sudoku-challenge`
site, just organized to hold more than one puzzle type under one domain.

## Layout

- **`index.html` / `css/hub.css`** — the hub landing page, listing every
  puzzle type as a card.
- **`css/hub-nav.css`** — the thin nav strip shown at the top of every
  puzzle type's own page, linking back to the hub and across puzzle types.
  It reads each host page's own `--ink` / `--accent` / etc. CSS variables,
  so it always matches that page's palette without needing its own theme.
- **`/sudoku/`** — the original sudoku site, migrated in unchanged apart
  from URLs/paths. See `sudoku/` for its own generation pipeline, workflow
  hookup, and notes (unchanged from the original `sudoku-challenge` repo).
- **`/kakuro/`** — placeholder page ("coming soon") until the kakuro
  generator is built.
- **`.github/workflows/daily-puzzles.yml`** — one consolidated nightly
  workflow that runs each puzzle type's generator script and commits new
  puzzle files. Add a new step here for each puzzle type as it ships.
- **`sitemap.xml`** — a sitemap *index* at the root, pointing at each
  puzzle type's own `sitemap.xml` (e.g. `sudoku/sitemap.xml`), which is
  regenerated by that type's generator script on every run.

## Migrating from sudoku.souravkhoso1.com

This hub takes over as the canonical home for the sudoku puzzle
(`puzzles.souravkhoso1.com/sudoku/`). The old `sudoku-challenge` repo/domain
should be turned into a redirect (preserving `?date=` links) rather than
deleted, so existing search rankings and bookmarks aren't broken outright.

## Setting it up

1. Push this repo to `souravkhoso1/puzzles` on GitHub.
2. **Settings → Pages**: deploy from branch `main`, folder `/ (root)`.
3. **Settings → Actions → General**: set "Workflow permissions" to
   **Read and write permissions** (the nightly job needs to push commits).
4. **Settings → Pages → Custom domain**: `puzzles.souravkhoso1.com` (matches
   the `CNAME` file already in the repo). Add the corresponding DNS record
   at your domain registrar.
5. Puzzles already exist for `sudoku/puzzles/2026-08-01.json` through
   `2026-09-08.json`, so the sudoku page works immediately. After that, the
   scheduled Action takes over.

## Adding a new puzzle type

Follow the pattern in `/sudoku/`:

1. New folder at the repo root (e.g. `/kakuro/`) with its own
   `index.html`, `css/`, `js/`, `scripts/generate-daily-puzzle.js`, and
   `puzzles/` directory.
2. Include `../css/hub-nav.css` and add the nav strip markup (see
   `sudoku/index.html` for the exact snippet) so it's reachable from every
   other puzzle page.
3. Add a card to the root `index.html` puzzle grid.
4. Add a generator step to `.github/workflows/daily-puzzles.yml`.
5. Add its `sitemap.xml` as a `<sitemap>` entry in the root `sitemap.xml`.
